## 1. 실행 방법

1. `dijkstra_maze_web` 폴더를 통째로 학생에게 배포합니다.
2. **`로컬서버_실행.bat`을 더블클릭**하면:
   - PC에 설치된 파이썬으로 `python -m http.server 8000`을 실행하고
   - 자동으로 브라우저에서 `http://localhost:8000`을 엽니다.
   - 창을 닫으면 서버가 꺼지므로, 작업하는 동안 창을 열어두라고 안내됩니다.
3. 파이썬이 PC에 없으면 배치 파일이 설치 안내 메시지를 띄웁니다
   (python.org에서 설치 시 "Add python.exe to PATH" 체크 필요).
4. `index.html`을 그냥 더블클릭해서 `file://`로 열어도 페이지는 뜨지만,
   상단에 "로컬 서버로 다시 실행해 달라"는 경고 배너가 뜹니다. 채점 자체는
   Pyodide(CDN)를 쓰기 때문에 file://에서도 동작은 하지만, 이후 작업(파일
   업로드 등 File System Access API)은 반드시 `http://localhost`가 필요하므로
   지금부터 로컬 서버 사용을 권장/습관화하는 것이 좋습니다.
5. 인터넷 연결이 필요합니다 (Pyodide를 CDN에서 최초 1회 내려받음, 이후에는
   브라우저 캐시를 씀).

## 3. 채점은 어떻게 동작하나요?

- 브라우저에서 [Pyodide](https://pyodide.org)(파이썬을 브라우저 안에서 돌리는
  런타임, WebAssembly 기반)를 CDN에서 불러옵니다. 첫 채점 시도 시 로딩하며,
  로딩 중에는 안내 배너와 버튼 비활성화로 표시됩니다. 로딩 실패 시 채점
  버튼이 비활성화되고 에러 배너가 뜹니다 (조용히 넘어가지 않음).
- **behaviour 모드 (4개 TODO: 2, 3, 4, 5)**: 학생 코드를 그대로 가져다가,
  격리된 미니 테스트 환경(가짜 Cell/Maze/Player 등)에 끼워 넣고
  **행동(behaviour)만** 비교합니다. 변수 이름이 다르거나 코드 구조가 달라도
  "행동이 같으면" 통과합니다(요구사항의 핵심 — `tests/`의 회귀 테스트가 이를
  실제로 검증합니다). **TODO 2는 완전히 결과(최종 위치/moved) 기반**이라,
  `try_move`를 아예 호출하지 않는 구현도 결과만 맞으면 통과합니다. TODO 5
  (Dijkstra 완화)는 Part 1/2 + Part 2/2로 나뉘어 각각 독립 채점되며, 신선/
  개선/비개선/음수 가중치 4가지 경우를 모두 확인합니다. 재귀/루프 관련
  하네스는 하드 캡을 걸어서, 학생 코드가 잘못돼도 브라우저가 멈추지 않도록
  했습니다.
- **syntax 모드 (5개 TODO: 1, 6, 7, 8, 9)**: 정답이 하나가 아닌 자유 설계
  문제라서, `ast.parse`로 문법 확인 + 실행 시 에러가 없고 필수 변수명이 전부
  정의됐는지만 완료 처리 기준으로 삼습니다. 타입/범위/딕셔너리 키 보존 등은
  비차단 "참고" 메시지로만 안내합니다. TODO 9는 추가로 **캡스톤 잠금**이
  걸려 있어서, 채점 결과와 별개로 다른 모든 Bonus가 완료/건너뛰기 되기
  전까지는 애초에 열리지 않습니다.
- 에러 메시지는 항상 "무엇이 맞았고 무엇이 틀렸는지"를 구체적으로 알려주도록
  작성했습니다 (`✓ ... / ✗ ...` 형태). 파이썬 문법 오류(SyntaxError 등)는
  로직 검사보다 먼저, 줄 번호와 함께 표시됩니다. **주석은 어디에, 어떤
  들여쓰기로 있든 채점에 전혀 영향을 주지 않습니다** (실제 파이썬과 동일 —
  과거 이 부분에 실제 버그가 있었고 수정되었습니다, 4절 참고).
- **채점 하네스(테스트 코드)는 정답을 담고 있지 않습니다.** 정답과 비교하는
  게 아니라, 몇 가지 입력값에 대해 기대되는 "결과"만 확인합니다.
